# 他農場に出す手順（マルチテナント）— HSS動画試験（hss-exam-video）

第2弾契約書 `~/ottlink-docs/multitenant/r2/CONTRACT-R2.md`（2026-10-07）の対応。

## 方式
**キット方式（静的アプリ）＋農場ごとに専用の GAS**。
設定は元から `config.js`（`CONFIG`）1か所。農場別の配布物 `dist/<id>/` を、`tenants/<id>.json` と環境変数からコマンド1本で作る。
結果の記録先は農場ごとに別の GAS・別のスプレッドシート（`gas/DEPLOY.md`）。農場Aの GAS と B の GAS は別なので、A の結果が B のシートに入ることも、B の管理者が A の結果を読むこともない。

| 項目 | 既定（ヒラノ版・何も指定しない） | 他農場の配布物 |
|---|---|---|
| 会社名（5言語）・題名・manifest・QR ページ | 株式会社ヒラノ（今のまま） | `company.ja/en/vi/id/es` |
| 権利表記（`© …`） | 今のまま表示 | 既定で出さない（`copyright.mode: "show"` の農場だけ残す） |
| 本試験パスワード | 今のハッシュ（変更なし） | 環境変数 `TENANT_EXAM_PASSWORD` から作った SHA-256 |
| 結果の記録先（GAS URL）・管理者メール・公開 URL | 今の値 | `webhookUrl`・`adminEmail`・`appUrl` |
| パスワードの総当たり対策 | なし（従来どおり。`security.pwMaxTries: 0`） | 5回まちがえると300秒ロック（端末内） |
| SW のキャッシュ名 | `hss-exam-video-vNN` | `…-vNN-<id>` |

## 新しい農場を1つ追加する（コマンド1本）
1. （1回だけ）その農場の Google アカウントで GAS を作る（`gas/DEPLOY.md`。**`node tools/build-tenant.mjs <id>` が作る `dist/<id>.setup/Code.gs`**（公開しない別フォルダ）を貼る → スクリプトプロパティ `ADMIN_EMAIL` に日次サマリーの宛先 → ウェブアプリ「全員」で公開 → `/exec` URL を控える）。
2. `cp tenants/demo-farm.json tenants/<id>.json` して会社名5言語・`webhookUrl`・`adminEmail`・`appUrl` を書く（パスワードはここに書かない。書くとビルドが止まる）。
3. `TENANT_EXAM_PASSWORD='<本試験パスワード>' node tools/build-tenant.mjs <id>`
   （または git に入れない `tenants/<id>.secret.json` に `{"examPassword":"…"}`。`.gitignore` 済み）
4. `dist/<id>/` を農場専用のホスティング（農場ごとに別オリジン）に置く。

ビルドは出力に「ヒラノの記録先・パスワードのハッシュ・会社名・管理者メール」が1つでも残ると失敗して `dist/<id>/` を消す。ヒラノの値を他農場に指定するとビルドが止まる。ビルドは本番へ何も送らない。
🚨 **問題と動画はヒラノ撮影の素材のまま同梱される**（`videos/`・`data/questions.json`。サイズ・問題数はその時点の本線の内容）。他農場に出す前に社長判断が必要（肖像・撮影許可・場面が他農場の実態と合うか）。農場の素材に差し替えるには `tenants/<id>.json` の `"contentDir"` に `data/` と `videos/` を入れた別フォルダを指定する（ビルドが入れ替える）。検査用に動画なしで作るなら `--no-videos`。

## GAS 側の変更（リポ内の `gas/Code.gs`・本番 GAS は未反映）
- 日次サマリーの宛先 `ADMIN_EMAIL` は、スクリプトプロパティ `ADMIN_EMAIL` があればそちらが優先。無ければ従来の値（リポの `gas/Code.gs`＝既存のヒラノのデプロイはそのまま動く）。
- **他農場用の `<out>.setup/Code.gs`**（`TENANT_MODE = true`）は既定の宛先が空で、`ADMIN_EMAIL` 未設定なら日次サマリーを**送らない**（ヒラノのアドレスへのフォールバックなし・コードにヒラノのメールを含まない）。
- 反映手順（社長作業・任意）: GAS エディタに貼り直し →「デプロイを管理」→ 鉛筆 →「新バージョン」。反映しなくてもアプリは今のまま動く。

## 契約書の合格条件との対応
| # | 条件 | 状態 |
|---|---|---|
| 1 | 農場名・合言葉・秘密が埋め込まれていない | 他農場の配布物は満たす（設定ファイル＋環境変数・ハッシュのみ。ビルドが検査）。ただし**問題・動画の素材**はヒラノ撮影（`contentDir` で差し替え可）。リポ内の既定はヒラノ版の現行値（条件6のため） |
| 2 | 農場追加がコマンド1本 | 上の手順 3（GAS の用意は農場ごとの初回作業） |
| 3 | A は B を読めない・書けない | 農場ごとに別 GAS・別シート。配布物に他農場の記録先・メール・会社名・ハッシュが入らない（`tests/tenant-isolation.test.js`）。受験者から GAS への送信は元から共有の鍵を持たない公開 POST（静的アプリの性質）。**各農場の GAS は別なので他農場には届かない** |
| 4 | 合言葉の入口に回数制限 | 他農場の配布物は端末内で5回/300秒（既定）。⚠ 静的アプリなので localStorage を消せば解除でき、パスワードの検証自体が端末内のハッシュ照合＝抑止力でありサーバ側の認証ではない（問題も端末に配られる）。ヒラノ版は従来どおり制限なし（`config.js` の `pwMaxTries` を 1 以上にすれば有効） |
| 5 | 権利表記の出し分け | 他農場は既定で `©` を出さない。`copyright.mode: "show"` で残せる |
| 6 | 既定でヒラノの動作が変わらない | `config.js` は `security` 行の追加以外 HEAD と同じ（テストで比較）。既定は回数制限なし。変更は `sw.js` の CACHE 名 v6→v7 のみ |
| 7 | 既存テスト全緑＋分離テスト | `node tests/e2e.js` / `node tests/review-e2e.js` / `python validate.py` / `node verify_logic.js` / `node tests/tenant-isolation.test.js` |

## 限界
- 「HSS認定制度」という制度名と、動画に映る現場・人物はヒラノ版のものがそのまま残る（会社名のみ差し替え）。
- 受験者 → GAS の送信に農場側の秘密は無い（公開 POST）。偽の結果を送られても他農場のシートには入らないが、その農場のシートには入りうる（正本は問題マスタとの照合・`検算`列）。

## 出力先の安全（V5 検証対応 2026-10-07）
- `--out <dir>`: 既存フォルダは「前回このツールが作った印ファイル `.tenant-build`（同じ id）」がある場合だけ消して作り直す。印が無い空でないフォルダ・ファイル・`/`・ホーム・リポ・リポの親・一時フォルダ・リポ内（`dist/` 以外）は**拒否して何も消さない**（`tests/tenant-isolation.test.js` に破壊テスト）。
- 出力は2フォルダ: 公開用 `dist/<id>/` と、非公開 `dist/<id>.setup/`（農場用 `Code.gs`＋README）。
- パスワードのロックのカウンタは本試験とデモで別キー（デモで間違えても本試験をロックしない）。

## 他農場版の既知の制約（元からの仕様・他農場に出す前に理解しておくこと）
- **正解入りの `data/questions.json` が公開配信される**: 静的アプリのため、本試験パスワードは問題の閲覧を防がない（ブラウザの開発者ツールで正解が読める）。パスワードは「受験を始める人の絞り込み」で、問題の秘匿ではない。
- **GAS への結果送信は無認証の POST**: URL を知る人は任意の氏名・得点・合否の記録を、その農場のシートへ書ける（検算列は申告の素朴な改ざんを検知するだけ）。他農場のシートには届かないが、その農場の認定記録の信頼性は「採点は問題マスタとの照合で行う」運用に依存する。サーバ側で採点する方式が要る農場には hss-other-farm（筆記）を使う。
- パスワードの回数制限は端末内（`localStorage` を消せば解除できる）。
